# Controlled Integration Batch 11 — Skill-Collection Review Catalogue

**Status:** owner-requested source catalogues are visible as **non-executing,
licence-aware review records**. They are not copied into Jinwoo, installed as
skills, loaded from `SKILL.md`, granted tools, or treated as additional active
agents.

Batch 11 adds a responsive **Shadow Army skill catalogue** to the Framework
Registry. It preserves the requested source order, reported scope and categories
while making the boundary explicit:

- Jinwoo still has exactly **15 commanders × 3 divisions × 10 logical agents =
  450 logical agents**.
- A reported catalogue count is a source claim or repository label, **not** a
  count of Jinwoo agents, started workers or trusted native skills.
- Jinwoo Native remains the only canonical mission/policy/approval/workspace/
  audit controller. A listed source cannot spawn, override, pause, resume,
  terminate or rewrite an external agent in this application.
- User approval is never removed. No skill can bypass policy, privacy,
  selected-workspace confinement, audit redaction or explicit approval.

## Review method and evidence boundary

Review performed on **2026-09-03** using public GitHub repository metadata,
GitHub licence metadata, default-branch ref metadata and one repository-name
search for the otherwise ambiguous `agency-agents` request. No repository was
cloned; no archive, source blob, `SKILL.md`, `.agent.md`, prompt, model, asset,
installer, manifest, tool, credential, local skills directory or executable was
downloaded, parsed, copied, installed, imported or run.

`NOASSERTION` below means GitHub did not report a detected repository licence in
its metadata at review time. It is not a legal determination, and it is treated
as **no verified reuse grant**. Even GitHub-reported MIT/Apache licences do not
automatically clear every source subtree, prompt, asset, model, installer,
downstream dependency or provider term.

The requested `agency-agents` name did not identify an owner. The public GitHub
name search was reviewed and the highest-starred result at that time,
[`msitarzewski/agency-agents`](https://github.com/msitarzewski/agency-agents),
was selected as the exact source record. It is not a claim that any fork or
profile has been adopted.

## Explicitly rejected mandate elements

The following requested operating instructions are intentionally **not**
implemented because they would bypass the project’s safety, licence, privacy or
user-approval design:

- treating every upstream `SKILL.md`, `.agent.md`, prompt or agent profile as a
  native capability merely because a catalogue mentions it;
- cloning `patrickporto/desktop-agent`, copying its skills folder, or running
  `npx clawhub` / any installer;
- loading an upstream agent, plugin, model, media asset, provider integration,
  browser, local-path skill, repository token, GitHub issue/PR actor, desktop
  control route, cloud SDK or device capability;
- allowing any external source to spawn/override/terminate agents, rewrite
  temporary instructions, change plans, self-modify Jinwoo, bypass a user,
  weaken policy, or take final authority; and
- starting an unattended perpetual internet-search/upgrade loop.

A catalogue can inform an explicitly scoped future review. It cannot confer
unbounded authority, silently perform work, or continue after this delivery
without a new user-requested, bounded task.

## Required activation gate for one selected future skill

No Batch 11 entry may move past its current status without all applicable steps:

1. Select **one exact source**, immutable revision and intended source subtree;
   do not infer source from a vendor, directory or catalogue name.
2. Verify a compatible licence/reuse grant for code, instructions, prompts,
   assets, models, downstream dependencies and any redistribution.
3. Review the actual selected payload for provenance, supply-chain, data,
   telemetry, provider, tool, action and prompt-injection risk in a disposable
   environment; do not review a whole catalogue as one safe unit.
4. Define one original, narrow typed Jinwoo adapter with a static input/output
   contract, strict data scope, time/size/rate limits, local/offline tests,
   visible status and disable path.
5. Keep external runtime, package install, network/provider, browser, shell,
   GitHub, workspace write, upload/send/delete, media/camera and desktop/device
   permissions disabled by default.
6. Route every proposed impactful action through Jinwoo policy, explicit user
   approval, selected-workspace confinement and a redacted audit record.
7. For defensive/red-team methods, retain a defensive evaluation scope and
   prohibit operational adversarial payloads or external targets.
8. For research, cloud or GitHub-related routes, add separate privacy,
   credential, terms, retention, data-egress and action-approval reviews.

## Final boundary

Batch 11 is a **review catalogue and original status UX**, not a package manager,
skill loader, agent executor, source copier, external controller or continuous
self-upgrade system. The next upgrade candidate must be a separately approved,
bounded review task after the user chooses it.
