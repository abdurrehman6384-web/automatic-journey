as non-executing capability contracts. No Batch 05 upstream source, skill pack,
script, package, binary, model, Docker image, sandbox, browser, MCP server,

right.

## Security, privacy and content rules

### Media rules

- Only user-owned or explicitly authorised local media may ever be considered.
- No scraping, streaming, ripping, protected-content bypass, YouTube/social
  download, publication or upload route is created by this batch.
- A future edit, render, transcript, export or share operation needs an exact
  action preview, chosen workspace/media root, storage/retention decision and
  explicit user approval.
- Model weights and third-party media assets have their own licences and cannot
  be downloaded automatically.

### Cybersecurity rules

The community cybersecurity catalogue is restricted to defensive, authorised
work: standards mapping, threat modelling, secure configuration, risk reports
and mitigation planning. It is not a licence to target systems or activate
penetration-testing, red-team, malware, credential, phishing, evasion,
exfiltration or scanning capabilities. Greed's existing no-scan endpoint
remains the only security-planning surface and still reads no files or Git
history.

### Tool, browser and MCP rules

Composio, Stagehand, LangChain Community and MCP catalogues are not blanket
“plug-and-play” permissions. Each future connector/server/tool needs its own:

1. exact source/version/licence and dependency review;
2. narrow typed input/output contract;
3. data classification, retention and outbound-provider consent review;
4. explicit account/OAuth secret handling outside the browser bundle;
5. domain/network/SSRF controls where relevant;
6. selected Workspace Guard confinement for file operations;
7. exact action preview and separate user approval for every impactful call;
8. redacted audit record, timeout, output cap, stop switch and rollback path.

No filesystem, PostgreSQL, Brave/search, fetch, browser, Docker, Spotify,
Figma, crypto or other server can be enabled simply through a list entry.

### Android boundary

Open-AutoGLM is recorded as a **queued** companion-phase concept only. It does
not alter desktop V1 or grant access to a phone, Accessibility, screen pixels,
notifications, touch/keyboard input, device files or accounts. Any mobile route
needs a separate reviewed Android design and device-local consent flow.

## What is implemented locally

- `GET /api/frameworks` exposes all 21 Batch 05 records with source URL,
  licence state, commander owner, capability tags, activation boundary and
  non-executing status.
- The Settings **Framework boundaries** panel renders the new media, defensive
  security, skill-library, connector, browser, MCP, multi-agent, science and
  Android lanes.
- Safe `POST /api/frameworks/{framework_id}/dry-run` plans are available for
  reviewed non-queued records. They use at most Planner, Executor and Verifier
  roles, return `external_runtime_invoked: false`, and append no raw prompt,
  source URL, key, media or workspace content to the audit record.
- The `envagent-source-intake` card intentionally does not show a dry-run
  button in the UI. It records the requested capability but blocks source work
  until the owner supplies the exact GitHub URL and licence.
- Jinwoo Native Control & Audit Review now verifies Batch 05 inventory plus all
  restricted-source, reference-only, archived, queued and source-intake locks.
